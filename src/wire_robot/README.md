# ワイヤ吊り下げ式ロボット 制御プログラム

Raspberry Pi 4B ＋ DCギアモータ4個（エンコーダなし）＋ IBT-2(BTS7960)×4 ＋ PS5コントローラ ＋ IMU(MPU6050)

OS は Raspberry Pi OS（64bit, Lite）。仕様の全体は同梱の仕様書 PDF を参照。

## 構成

| ファイル | 内容 |
|---|---|
| `config.py` | ピン番号・回転方向・ゲイン・ボタン割り当て。**基本ここだけ編集** |
| `main.py` | 操縦プログラム本体（50Hzループ、走行／ワイヤ調整の2モード） |
| `mixer.py` | スティック入力 → 4ドラムの指令値への変換 |
| `controller.py` | 傾き補正のPI制御、加速制限 |
| `motors.py` | モータドライバ（IBT-2 / 他ドライバも切替可） |
| `imu.py` | MPU6050読み取り、相補フィルタによる傾き推定 |
| `gamepad.py` | コントローラ入力（evdev、通信途絶0.2秒で停止・切断時は自動再接続） |
| `tools/` | 配線・IMU・コントローラの確認用スクリプト |
| `tests/` | ハードなしで動くテスト（`test_logic.py` 制御、`test_link.py` 通信途絶） |

## 配線（IBT-2 × 4）

| モータ | 役割 | RPWM | LPWM |
|---|---|---|---|
| UL | 左 上下プーリ（外側） | GPIO12 | GPIO13 |
| UR | 右 上下プーリ（外側） | GPIO18 | GPIO19 |
| LL | 左 左右プーリ（内側） | GPIO20 | GPIO21 |
| LR | 右 左右プーリ（内側） | GPIO23 | GPIO24 |

| 共通 | ラズパイのピン |
|---|---|
| R_EN / L_EN（4台分） | GPIO26（物理37番）※各IBT-2上で R_EN と L_EN をつないで1本に |
| VCC（4台分） | **3.3V**（物理1番 or 17番） |
| GND | 物理6・9・14・20・25・30・34・39番のどれか |

- **IBT-2 の VCC は 3.3V** から取る（5V にすると入力バッファ 74HC244 の H 判定が 3.5V 以上になり、Pi の 3.3V 出力では不安定）
- R_IS / L_IS（電流検出）は未使用・未接続
- MPU6050 は VCC=3.3V(物理1番), SDA=GPIO2(物理3番), SCL=GPIO3(物理5番)
- ハブ基板に 3.3V と GND のラインを作り、4台の IBT-2 と MPU6050 に分配する
- B− は必ず太い線でリポの − に直接つなぐ（IBT-2 内部で信号GNDと B− がつながっているため、細い信号GNDにモータ電流を流さない）
- ピンを変えたら `config.py` の `MOTORS` / `ENABLE_PIN` を書き換える

### EN の配線（2通り）

| 方式 | 配線 | `config.py` |
|---|---|---|
| GPIO26 で制御（推奨） | R_EN + L_EN → GPIO26 | `ENABLE_PIN = 26` |
| VCC に直結 | IBT-2 上で VCC・R_EN・L_EN をつなぐ | `ENABLE_PIN = None` |

どちらでも通常の停止は同じように効きます。GPIO26 方式は、待機中に PWM 線へノイズが乗っても回らないこと、将来ウォッチドッグ回路を EN 線に入れられることが利点です。プログラムの強制終了やラズパイのフリーズ時はどちらの方式でも止まらない可能性があるため、最終的な非常停止はブレーカーで行います。

## 電源（スイッチ2系統）

モータ：12V 直交軸ウォームギアモータ（60kg·cm クラス）× 4

```
リポ ─┬─ DCブレーカー 15A（モータ電源SW 兼 過電流保護）─┬─ IBT-2 UL / LL（左）
      │                                                  └─ IBT-2 UR / LR（右）
      └─ トグルSW（DC定格）─ DCDC 5V 3A以上 ─ ラズパイ（＋ハブ基板＋IMU）
```

| 部品 | 目安 |
|---|---|
| モータ側ブレーカー | DC 15A（起動で落ちるなら 20A） |
| 幹線（リポ〜ブレーカー〜分岐） | AWG14〜16 |
| 分岐〜各IBT-2、IBT-2〜モータ | AWG18 |
| ラズパイ側スイッチ | DC 3A 以上 |

- スイッチは必ず **DC定格** のものを使う（AC用はDC大電流で接点が溶けることがある）
- GND はリポ付近の1点にまとめる（スター配線）
- **入れる順**：ラズパイ → プログラム起動 → ブレーカー　**切る順**：ブレーカー → ラズパイ
- ブレーカーがそのまま物理的な非常停止になる
- 電流値は一般的な仕様からの概算。銘板の定格・ロック電流を確認し、可能ならクランプメータで実測する

## 動作の考え方

| 動作 | UL（左外） | UR（右外） | LL（左内） | LR（右内） |
|---|---|---|---|---|
| 上昇 | 巻取 | 巻取 | 巻取 | 巻取 |
| 右移動 | 停止 | 停止 | 巻取 | 巻出 |
| 傾き補正（右が下がった） | 少し巻出 | 少し巻取 | — | — |

## セットアップ

```bash
sudo raspi-config        # Interface Options → I2C を有効化
sudo apt install python3-gpiozero python3-lgpio python3-evdev python3-smbus2 i2c-tools
i2cdetect -y 1           # 0x68 が見えればIMU接続OK
sudo usermod -aG input,gpio,i2c $USER   # 再ログイン後 sudo なしで動く
```

### ライトバー・振動の権限

ライトバーの色を変えるには、LED への書き込み権限が必要です。次の udev ルールを追加してください（追加しなくても操縦はできます。色が変わらないだけです）。

```bash
sudo tee /etc/udev/rules.d/99-dualsense-led.rules >/dev/null <<'RULE'
ACTION=="add", SUBSYSTEM=="leds", KERNEL=="*:rgb:indicator", RUN+="/bin/chgrp input /sys%p/brightness /sys%p/multi_intensity", RUN+="/bin/chmod g+w /sys%p/brightness /sys%p/multi_intensity"
RULE
sudo udevadm control --reload-rules
# 追加後、コントローラを接続し直す
```

振動は `input` グループに入っていれば追加設定なしで動きます。

### PS5コントローラのペアリング（Bluetooth）

```bash
bluetoothctl
  scan on
  # コントローラの CREATE + PSボタン を長押し（ライトバーが速く点滅）
  # "DualSense Wireless Controller" の MAC アドレスが出たら
  pair XX:XX:XX:XX:XX:XX
  trust XX:XX:XX:XX:XX:XX
  connect XX:XX:XX:XX:XX:XX
  exit
```
USBケーブルで繋いでも使えます。

## 初回の確認手順（この順番で）

1. **コントローラ** `python3 tools/gamepad_check.py`
   ボタン名が `config.py` と違えば書き換える
   続けて `python3 tools/link_check.py` で通信の生存確認（下記「通信途絶の停止」）
2. **モータ** `python3 tools/test_motors.py`
   **ワイヤを外すか、たるませた状態で**。`UL+` などで1秒回し、「+」で巻き取りにならないモータは `invert` を反転
3. **IMU** `python3 tools/imu_check.py`
   右側を下げて「加速度角」と「角速度」がプラスになるよう `IMU_AXIS_*` の符号を合わせる
4. **シミュレーション** `python3 main.py --sim`（モータとIMUがダミー、コントローラは実物）
5. **ワイヤ調整モードで張りを揃える**（下記）
6. **実機（低い位置で）** `python3 main.py --log run.csv`
   左右移動の向きが逆なら `LATERAL_SIGN = -1`

## 操作（PS5コントローラ）

スティックを **±0.2 より大きく倒している間だけ動き、離せば止まります**（押しっぱなしのボタンは不要）。

### 共通

| ボタン | 動作 |
|---|---|
| PSボタン | 走行モード ⇔ ワイヤ調整モード（スティックを離した状態で。切り替え時に振動） |
| × | 非常停止（ラッチ） |
| OPTIONS | 非常停止の解除（スティックを離した状態で） |

### ライトバーの色

| 色 | 状態 |
|---|---|
| 青 | 走行モード |
| オレンジ | ワイヤ調整モード |
| 赤 | 非常停止中 |
| 点滅 | スティックが中央に戻るのを待っている（離せば点灯に戻る） |

### 走行モード（青）

| 入力 | 動作 |
|---|---|
| 左スティック 上下 | 上昇／下降（4本同時） |
| 右スティック 左右 | 左右移動 |
| R1 | 押している間は高速 |
| △ | 傾き補正 ON/OFF |
| CREATE | 現在の姿勢を「水平」として記録 |

- 傾き補正はスティックを倒している間だけ効きます（止まっている間はモータは一切動きません）
- 上下と左右は同時に動かせます（斜め移動）。片方ずつにしたい場合は `AXIS_LOCK = True`（大きく倒した方だけが効く）

### ワイヤ調整モード（オレンジ）

肩ボタンの位置が、機体のドラムの位置に対応しています。**1回押すとそのモータが選ばれ、別のボタンを押すとそちらに切り替わります**（選んだときに短く振動）。

```
   L1 = 左上 (LL 左 左右プーリ)        R1 = 右上 (LR 右 左右プーリ)
   L2 = 左下 (UL 左 上下プーリ)        R2 = 右下 (UR 右 上下プーリ)
```

| 入力 | 動作 |
|---|---|
| L1 / R1 / L2 / R2 を1回押す | そのモータを選択 |
| 左スティック 上 | 選んだモータを巻き取り |
| 左スティック 下 | 選んだモータを巻き出し |

- モードに入った直後は何も選ばれていないので、スティックを倒しても動きません
- モータの切り替えはスティックを離した状態で行います
- 傾き補正は止まります。速度は `WIRE_ADJUST_SCALE` で変えられます
- 実機のドラム配置が違う場合は `config.py` の `WIRE_BUTTONS` で入れ替えてください

## 安全機能

- スティックを離す（±0.2 以内）／コントローラ切断／**通信途絶 0.2 秒**／Ctrl+C → 全モータ即停止＋IBT-2 の EN を L
- 起動直後・モード切替・非常停止の解除・コントローラ再接続・通信復帰のあとは、スティックが一度中央に戻るまで動かない（倒しっぱなしでの急発進防止）
- 停止中はウォームギアで保持
- Pi の起動直後は GPIO26 がプルダウンなので、プログラムが動くまでモータは回らない
- 走行モードで傾きが `TILT_LIMIT_DEG` を超えたら移動を止め、補正だけ行う
- 加速は `SLEW_RATE` で制限、停止は即時

## 通信途絶の停止（ウォッチドッグ）

Bluetooth の電波が途切れても、カーネルが「切断」と判定するまで数秒かかることがあり、その間はスティックを倒したままの値が残ります。これを防ぐため、DualSense の**モーションセンサ**デバイス（コントローラが静止していても毎レポートイベントが流れ続ける）を受信の証拠にしています。

- 最後の受信から `LINK_TIMEOUT_SEC`（0.2 秒）経つと「通信途絶」→ 全停止（表示 `[走行 通信途絶]`）
- 受信が戻っても、スティックが一度中央に戻るまで動かない（ライトバー点滅）
- モーションセンサが見つからない場合は「生存確認できません」と表示して**動かさない**（`LINK_REQUIRE_MOTION = True`）。古いカーネルなどでどうしても見つからない場合のみ `False` にする（従来どおりカーネルの切断判定だけになる）
- `--log` の CSV に `link`（状態）と `rx_age`（最後の受信からの秒数）を記録

確認（`python3 tools/link_check.py`）：

| 確認すること | 合格の目安 |
|---|---|
| 「生存確認: DualSense Wireless Controller Motion Sensors」と出る | 出ない場合は `ls /dev/input/` と `uname -r` を確認 |
| コントローラを机に置いたままでも受信が続く | 受信 100 回/秒以上 |
| 最大間隔 | 普段 50 ms 以下。作業位置まで離れても 100 ms 未満 |
| コントローラの電源を切る（PSボタン10秒長押し） | 約 0.2 秒で `lost` |

最大間隔がしきい値に近い（「しきい値に近い!」と出る）場合は、アンテナ位置を見直すか `LINK_TIMEOUT_SEC` を 0.3 程度に上げる。Wi-Fi（2.4GHz）を使っていると Bluetooth と干渉するので、可能なら 5GHz か有線にする。

この機能はコントローラ側の通信を見るもので、**ラズパイ自体のフリーズやプログラムの異常終了では止まりません**（EN へのハードウェアウォッチドッグは未実装）。最終的な非常停止はブレーカー。

## 調整のコツ

- まず `TILT_KI = 0` で `TILT_KP` を上げていき、揺れ始めたら半分に戻す → その後 `KI` を少し足す
- `--log` のCSVを見ると、θと各モータ指令の関係が分かる
- モータが低デューティで回らなければ `MIN_DUTY` を上げる

## 既知の制約（エンコーダなし）

- ワイヤの繰り出し量を測れないため、4本の長さは同期できない。上下移動中に内側ワイヤがたるむ・張りすぎることがある → ワイヤ調整モードで都度合わせる
- 左右移動中の高さのずれは補正できない（IMUで分かるのは傾きだけ）
- 将来エンコーダを付ける場合は `mixer.py` の出力を「目標速度」として扱い、モータごとに速度制御を追加する形で拡張できる
